# AI Artifact Workspace (feature branch)

> **Release update (2026-10-31):** The sections below describe the original local-volume artifact implementation. [PR #82](https://github.com/naim-munshi/aqlyra-rag-ai/pull/82) adds a default-off private S3-compatible backend. It is **not live or production-accepted**. Remote mode does **not** automatically migrate or dual-read older local artifacts; follow the [non-destructive storage rollout and acceptance guide](ARTIFACT_REMOTE_STORAGE_ROLLOUT.md) before considering activation. Preserve the local files, private bucket, and stable metadata-signing key throughout any migration and restore rehearsal.

Aqlyra generates actual downloadable .docx, .xlsx, .pptx, .pdf and .md
files. This is a separate authenticated service built around the existing
LLM and citation-validated RAG architecture. It does **not** modify
document indexing, embedding dimensionality, retrieval, current users,
conversations, project ownership, or database migrations.

## Routes

- Page: /artifacts (signed-in, routed from sidebar "AI Files")
- POST /api/v1/artifacts/generate: {title, prompt, format, document_ids?, confirm_share_documents?}
- POST /api/v1/artifacts/render: {title, content, format} (user edits)
- GET /api/v1/artifacts: list owner files (max 50)
- GET /api/v1/artifacts/{id}: editable Markdown source and metadata
- GET /api/v1/artifacts/{id}/download: streamed attachment
- DELETE /api/v1/artifacts/{id}: delete owner's artifact

The frontend uses same-origin, cookie-to-bearer authenticated Next.js
proxies under /api/artifacts and checks request origins on mutations.

## Security and RAG preservation

- No arbitrary code execution, eval, Office macros, Python generated by LLM,
  shell invocation or external converters.
- Files use 36-character server-generated UUID IDs on the existing
  persistent UPLOAD_DIR volume in user-UUID-scoped directories. Never
  accept user paths. No database migration or existing uploads changed.
- No automatic indexing of generated files or cross-user access. New
  files are available to the user as downloads, not silently inserted
  into Knowledge/RAG collections.
- Per-file limit: 5 MiB; 50 artifacts per account; prompt 4,000
  characters; generated source 24,000 characters.
- Excel formula-like strings are written as escaped literal text.
  Formulas are not evaluated. If numeric formulas are required,
  add a separate safe, approved formula interpreter in a later PR.
- Private-document generation requires explicit consent from the user
  (`confirm_share_documents=true`). Selected excerpts may be transmitted
  to the configured AI service; missing consent fails closed with HTTP 422
  before retrieval/model execution. The UI does not permit generation
  with private sources until the user checks the consent control.
- If document_ids is nonempty, every referenced document must be
  owned by the user and indexed (status ready). The backend calls the
  existing answer_question() service with an explicit document scope.
  This service already validates citations and grounding. Empty or
  unsupported evidence fails closed (422); no file created.
- If no document_ids are supplied, Aqlyra uses its already configured
  LLM provider; it never silently presents deterministic test output
  as real AI. Production still requires a real provider to be configured.
- Editing and saving a grounded document creates a new *user-edited*
  version. The edited copy is not labelled citation validated.
- File source is plain Markdown and can be edited before re-rendering.
  Downloaded binary files are real openable Office / PDF files, but
  rich WYSIWYG Office editing is out of scope for this first version.
- File deletion is permanent. Each save creates a new file, not an
  in-place overwrite. Existing documents and memories are untouched.

## International text / layout limitations

Word/PowerPoint/Markdown preserve Unicode text as supported by each
consumer's fonts. PDF in this first version uses DejaVu for Latin text;
complex Japanese/Bengali/Arabic shaping and full glyph coverage are
not yet guaranteed. Do not claim multilingual PDF production readiness.
Markdown tables are rendered as rows in XLSX, and long paragraphs are
simplified to slides in PPTX; this is functional structured export,
not a pixel-perfect Office design engine.

## Audit hardening follow-up

- All source Markdown line counts, XLSX table widths/row counts and PPTX slide
  counts fail with a clear error rather than silently discard excess content.
- Document-grounded AI exports append owner-private citation provenance:
  filenames, page numbers where available, and referenced document IDs.
- Per-user artifact quota now uses filesystem flock on the same persistent
  volume across parallel workers. Deploying independent, non-shared upload
  volumes is still not supported by this coordination scheme.
- Generic AI outputs over the 24,000-character limit fail; requests must be
  shortened. There is **not yet** a map/reduce multi-section long-report job.
- PDF complex-script font coverage, worker isolation and full WYSIWYG editing
  remain outstanding release gates. Do not label this as production-ready.
