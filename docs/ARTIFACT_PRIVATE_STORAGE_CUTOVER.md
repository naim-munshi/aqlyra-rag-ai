# Aqlyra — private, restart-durable generated artifacts (opt-in)

This runbook covers **generated** PDF, DOCX, XLSX, PPTX and Markdown
artifacts. It does **not** claim that original uploaded RAG source files are
durable. The authenticated document-ingestion/storage lifecycle has its own
release gate. Keep the protected Vercel frontend closed to public traffic.

## Existing behavior and rollout boundary

- Existing `backend/app/services/artifact_storage.py` remains the
  default local provider. The Free Render filesystem is ephemeral and
  must **not** be described as a persistent upload volume.
- The new `backend/app/services/artifact_remote_storage.py` is
  optional via `ARTIFACT_REMOTE_STORAGE_ENABLED=false` (default).
  No production state is changed merely by merging its source.
- The remote backend reuses Aqlyra's existing private, HTTPS-validated
  Neon S3 client, and requires `PRIVATE_OBJECT_STORAGE_ENABLED=true`.
  Browser uploads and public object URLs remain **disabled**; the S3
  bucket must be private, with non-public access credentials.
- The owner-specific storage namespace is
  `artifacts/<owner UUID>/<artifact UUID>.<format>` and
  `artifacts/<owner UUID>/<artifact UUID>.json`. Clients never choose
  keys, see S3 credentials, or receive presigned object download URLs.
- Private objects include a SHA-256 digest of generated bytes.
  Download verifies digest and byte count; tampering fails closed.
  The SQL PostgreSQL advisory transaction lock serializes per-owner
  quota checks across API workers (50 items/user).
- The final metadata JSON object acts as an inventory visibility marker.
  The underlying object store does not provide a multi-object transaction:
  interruption between object writes may leave orphan binary objects.
  A new internal read-only `audit_owner_inventory(user_id=...)`
  reports count-only `complete_records`, `missing_binaries`,
  `invalid_metadata`, `orphan_binaries`, `unexpected_keys`,
  and `total_objects` while holding the owner's PostgreSQL
  transaction advisory lock. It never lists filenames/keys in the
  response and never deletes data. It does not expose any public API
  and is intended for trusted operator-side diagnostics after private
  S3 credentials and feature gating have been validated. No automated
  garbage collection/deletion has been authorized. A nonzero anomaly
  count must block acceptance pending a human-reviewed recovery plan.

## Required configuration — **not configured by this code commit**

Use only trusted provider dashboards/secret managers for values. Do not
paste any secret, private object URL or user file into GitHub/ChatGPT.

```dotenv
# Opt-in only AFTER private provider and rollback acceptance.
PRIVATE_OBJECT_STORAGE_ENABLED=true
ARTIFACT_REMOTE_STORAGE_ENABLED=true
OBJECT_STORAGE_BUCKET=private-documents
AWS_ENDPOINT_URL_S3=<approved HTTPS Neon branch storage endpoint>
AWS_REGION=ap-southeast-1
AWS_ACCESS_KEY_ID=<private key>
AWS_SECRET_ACCESS_KEY=<private secret>
```

Keep `CLOUD_UPLOAD_PUBLIC_ENABLED=false` and the separate frontend
`NEXT_PUBLIC_CLOUD_UPLOAD_ENABLED=false` unless their independent
security gates have passed. Do not use an unrestricted/public S3 bucket.

## Pre-enable acceptance (currently BLOCKED)

1. Confirm the bucket `private-documents` is private on approved Neon
   project `rough-river-66110449`, branch `br-morning-water-a1lgl3s4`.
   Verify provider IAM scope and private HTTPS endpoint. The branch may
   change after a disaster recovery event; never silently point it
   elsewhere.
2. Verify the registered production user count, any existing artifacts
   on local disk, and migration obligations. **Enabling the remote mode
   does not migrate or combine older local artifacts**: if local artifacts
   exist, preserve and safely migrate them first. Never silently discard
   or hide user documents.
3. On an isolated, authenticated staging environment and dedicated test
   user IDs, exercise create/list/get/download/delete for every format,
   two-user foreign-owner denial, malformed IDs, quota concurrency,
   SHA-256 mutation detection, failure during metadata publish, and
   private content never appearing in response logs.
4. Restart/redeploy the staging worker; confirm all five generated
   formats and metadata survive and are retrievable after restarting
   all API processes. Verify a second worker sees the same records.
5. Test PostgreSQL advisory lock failures, private-bucket IAM denial,
   S3 downtime, oversized output and source-injection behavior. The API
   must deny requests safely rather than falling back to ephemeral disk.
6. Confirm restart recovery, private bucket retention/backup policy,
   object lifecycle and orphan cleanup; monitor quotas/costs within the
   free allowance. Do not purchase resources without owner approval.
7. Only then approve the remote feature gate on the correct backend.
   Keep public access/registration disabled until separate RAG, Study
   Abroad, LiveKit Voice and real multi-user security gates pass.

## Rollback

For a provider outage, disable new generation or put the feature into
maintenance mode; **do not toggle the remote flag off as a data recovery
strategy**. Doing so exposes the old local provider and temporarily
hides remote artifact history. Repair private access or migrate data
with verified object checksums and owner-specific access before a
controlled transition. Never clear the S3 prefix or reset the database.

## Verified evidence boundary

Offline regression tests use only fake private S3 objects and an
advisory-lock surrogate for other tests. A separate test now exercises
real PostgreSQL advisory transaction locking on independent sessions
under both PG16/PG18, and new fake-S3 tests exercise read-only
inventory anomaly counting and tenant separation. These checks
still are **not** proof of real Neon S3 access,
production credentials, live user isolation or restart durability.
The live rollout remains BLOCKED until all pre-enable checks pass.
